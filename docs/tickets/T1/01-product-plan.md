# T1 — Product plan

Ticket row (Tech Spec, Build plan): **T1 Scaffold** — "Next.js + TypeScript strict, Tailwind, shadcn/ui init, ESLint, Prettier, scripts, folder structure" · Depends on: — · Done when: "App runs; lint and typecheck pass".

T1 is infrastructure only. It ships no product screens, no data and no components beyond what `shadcn init` generates.

## Scope

**In**

- TypeScript strict: keep `"strict": true` in `tsconfig.json` (already set by create-next-app) and keep the `@/*` → `./src/*` alias.
- Tailwind CSS v4 (already installed): keep it working after the stylesheet moves to `src/styles/globals.css`.
- shadcn/ui init: `components.json` generated, primitives directory `src/components/ui`, utils at `src/lib/utils.ts` (`cn` helper), CSS path `src/styles/globals.css`, aliases using `@/`.
- ESLint: keep `eslint.config.mjs` (eslint-config-next); make it not conflict with Prettier.
- Prettier: config file + ignore file, and a `format` script.
- npm scripts (final set): `dev`, `build`, `start`, `lint`, `typecheck` (`tsc --noEmit`), `format` (Prettier write over the repo). Optional `format:check` for CI is allowed.
- Folder structure from the Tech Spec "Stack and project structure" (see list below), with `.gitkeep` in every folder that has no file yet.
- Design-token file location: move `src/app/globals.css` → `src/styles/globals.css`, update the import in `src/app/layout.tsx`, and declare the **provisional token names and values exactly as listed in the Tech Spec** (`--brand`, `--brand-foreground`, `--brand-soft`, `--ink`, `--ink-muted`, `--surface`, `--surface-alt`, `--surface-dark`, `--border`, `--success`, `--warning`, `--danger`, `--radius-sm`, `--radius-md`, `--radius-lg`, `--font-sans`). T2 replaces the values with the real brand; T1 only sets up names, location and the Tailwind mapping hook.
- Minimal placeholder home page at `/` replacing the create-next-app boilerplate (product name and a one-line "under construction" note, styled only with tokens). Root `metadata` title/description changed from "Create Next App" to Chores For Me.
- Remove create-next-app boilerplate that is no longer referenced (default page content, unused starter SVGs in `public/` if present).
- Install the fixed stack packages (see "Packages" below).

**Out**

- Any real screen, layout component (Header, Footer, AppShell, BottomNav, SideNav), state components (Loading/Empty/ErrorState), `/styleguide` page, real brand colours, logo, fonts, shadcn theming → **T2**.
- `types.ts`, `constants.ts`, seed data, mock services, Zustand stores, `analytics.ts` → **T3**.
- Adding any shadcn primitive beyond what `init` generates (e.g. button, dialog) → added by the ticket that first needs it (T2 onwards).
- Route pages under `(marketing)`, `(auth)`, `post-job`, `worker`, `dashboard` → T4–T10.
- Deployment → T12.

## Behaviour and rules

1. "Fixed stack: Next.js (App Router) + TypeScript strict, Tailwind CSS, shadcn/ui, React Hook Form, Zod, Zustand (persist), lucide-react. Do not add libraries without approval." (AGENTS.md)
2. "The stack is fixed; agents install the latest stable version of each at scaffold time and do not add other UI or state libraries without approval." (Tech Spec)
3. Quality: "ESLint, Prettier, `tsc --noEmit` | Scripts: `lint`, `typecheck`, `format`" (Tech Spec, Stack table). Package manager npm, Node LTS.
4. shadcn/ui: "Generated into `components/ui`, then themed with our tokens" (theming is T2).
5. Tailwind: "Tokens defined once as CSS variables and mapped in the Tailwind config" — with Tailwind v4 there is no JS config by default; the mapping lives in the CSS `@theme` block in `src/styles/globals.css` (see Open questions).
6. "Token names are fixed now; their values are provisional until ticket T2 replaces them." Components use tokens only, never raw hex values — the placeholder page must use no raw hex/one-off sizes.
7. Server components are the default; the placeholder page has no `"use client"`.
8. File names kebab-case, components PascalCase, one component per file.
9. "Every agent builds only that ticket's scope and never refactors unrelated files." "Agents do not commit."
10. No backend, no API routes, no third-party auth or payment SDKs.
11. PRD: "Environments: Hosted demo build for client review; no development build names visible" — the placeholder must not show "Create Next App" or other starter text.

## Open questions

1. **`@hookform/resolvers`** is needed to plug Zod schemas into React Hook Form but is not named in the fixed stack. Approve installing it (now or in T5)?
2. **`eslint-config-prettier`** (and optionally **`prettier-plugin-tailwindcss`** for class sorting) are dev tooling not named in the stack. Approve? Plan assumes `eslint-config-prettier` yes, Tailwind plugin no, unless told otherwise.
3. **Tailwind v4 has no `tailwind.config` file**; the spec says tokens are "mapped in the Tailwind config". Confirm mapping via the CSS `@theme inline` block in `src/styles/globals.css` is acceptable (recommended for v4) rather than adding a JS config.
4. **Token name collisions with shadcn**: shadcn init writes its own variables (`--background`, `--foreground`, `--primary`, `--border`, `--radius`, …) into the same file; `--border` is shared with our token list. T1 proposal: keep shadcn's variables as generated and add our provisional tokens alongside; T2 maps shadcn variables onto our tokens. Confirm.
5. **Dark mode**: neither spec mentions it. create-next-app and shadcn both add dark-mode variables. Remove dark mode (light only) in T1, or leave shadcn's `.dark` block untouched for T2 to decide?
6. **Fonts**: layout currently loads Geist via `next/font`; the provisional token is `--font-sans: 'Inter', system-ui`. Should T1 switch to Inter now, or leave font loading to T2 (which pulls real fonts from choresforme.com)? Plan assumes leave to T2, but the placeholder must not visibly rely on Geist-only styling.
7. **`package.json` lists `@tailwindcss/turbopack`** and there is no `postcss.config.mjs` in the repo. The lead engineer should confirm Tailwind actually compiles in both `dev` and `build`; if a PostCSS config is required, adding `@tailwindcss/postcss` counts as part of the existing Tailwind choice, not a new library.
8. **Route folder naming vs route map**: the folder structure uses `post-job/[step]/` and `worker/onboarding/[step]/`, while the route map lists fixed steps (`/post-job/category`, …). T1 creates the folders as the structure says; T6/T9 decide dynamic vs static segments.
